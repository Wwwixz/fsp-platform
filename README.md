# ФСП — платформа спортивного программирования

Полноценный MVP платформы Федераций спортивного программирования: соревнования,
команды, заявки с модерацией, результаты и аналитика организатора.

## Стек

| Слой      | Технологии |
| --------- | ---------- |
| Фронтенд  | React 19 + TypeScript + Vite + Tailwind CSS |
| Бекенд    | Java 21 + Spring Boot 3 (Web, Data JPA, Validation) |
| БД        | PostgreSQL 16 |
| Auth      | JWT (jjwt) + BCrypt |
| Инфра     | Docker, docker compose, nginx |

## Быстрый запуск

Нужен только Docker. Из корня репозитория:

```bash
docker compose up --build
```

После сборки:

- **Фронтенд**: http://localhost:5173
- **API бекенда**: http://localhost:8080/api/competitions

База при первом старте заполняется синтетическими данными автоматически
(демо-аккаунты, 8 соревнований, 10 команд, ~45 заявок, итоги прошедших турниров).

## Локальная разработка без Docker

```bash
# 1. База (или любая PostgreSQL с db=fsp, user=fsp, password=fsp)
docker run -d --name fsp-db -p 5432:5432 \
  -e POSTGRES_DB=fsp -e POSTGRES_USER=fsp -e POSTGRES_PASSWORD=fsp postgres:16-alpine

# 2. Бекенд (Spring Boot, порт 8080)
cd fsp-backend && mvn spring-boot:run

# 3. Фронтенд (Vite dev server, порт 5173, /api проксируется на 8080)
npm install && npm run dev
```

Сборка и проверка типов фронтенда: `npm run build`. Сборка бекенда:
`cd fsp-backend && mvn package`.

## Роли и сценарии (по ТЗ)

- **Спортсмен** — поиск соревнований с фильтрами (даты, формат, дисциплина),
  индивидуальные заявки (сценарий 7), команды и составы (сценарии 2–4),
  личный кабинет с подтверждёнными достижениями (сценарий 9), история результатов.
- **Региональный представитель** — заявки только своего региона, автоматическая
  проверка региона спортсмена при подаче заявок (сценарий 6, включая
  межрегиональные соревнования), аналитика (сценарий 10).
- **Федерация ФСП** — федеральные соревнования, куда заявки подают только
  региональные представители (сценарий 5), видит все заявки.
- **Организатор** — публикация итогов: места и баллы автоматически попадают
  в профили спортсменов и рейтинги команд (сценарий 8).

## API (основные endpoints)

```
POST /api/auth/register | /api/auth/login      — регистрация/вход (JWT)
GET  /api/auth/me                              — текущий пользователь
GET  /api/competitions                         — лента соревнований (публично)
GET  /api/competitions/{id}                    — детали, команды, итоги (публично)
POST /api/competitions                         — создать соревнование (организатор)
POST /api/competitions/{id}/results            — опубликовать итоги (организатор)
GET  /api/teams, /api/teams/top?competitionId= — рейтинги команд (публично)
POST /api/teams, POST /api/teams/{id}/join     — создать команду / вступить
GET  /api/applications                         — заявки для модерации (по роли)
GET  /api/applications/my                      — свои заявки
POST /api/applications                         — подать заявку
PATCH /api/applications/{id}                   — одобрить/отклонить (организатор)
GET  /api/results/my                           — история выступлений
GET  /api/cabinet                              — данные личного кабинета
GET  /api/analytics                            — сводка организатора
GET  /api/meta/disciplines | /api/meta/regions — справочники
```

## Структура

```
src/                  фронтенд (React): страницы, компоненты, api-клиент
fsp-backend/          бекенд (Java/Spring Boot)
  src/main/java/fsp/platform/
    auth/             регистрация, вход, JWT
    user/             пользователи, роли, личный кабинет
    competition/      соревнования, дисциплины, расписание
    team/             команды и составы
    application/      заявки и модерация
    result/           итоги и профили
    analytics/        сводка организатора
    seed/             синтетические данные для демо
docker-compose.yml    db + backend + frontend
```
